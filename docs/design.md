# Design decisions

## 1. A sidecar, not a module in the agent

Capture runs in its own container, and the agent has no access to what it records. A module inside the agent
would be recording itself: whatever it logged, the agent could skip, edit or delete. The PowerShell module in
this repo is for the host, to read the capture after the fact.

The sidecar is also the agent's only route out. `sidecar.yaml` declares two networks: `inside`, which is
`internal: true` (Docker gives it no gateway), and `outside`. `mitm` is on both; the agent is on `inside` only,
and nothing else is. A process in the agent that ignores the proxy settings has nowhere to go: the opt-in hole
that cooperative proxy variables leave is closed by the network, not by the agent's good behaviour.
`HTTP_PROXY` / `HTTPS_PROXY` stay set on the agent as a convenience, so ordinary tools find the proxy without
configuration; they are no longer the control. Claude.Agent's entrypoint proves this on every run with a direct
`curl --noproxy '*'` that must fail (`agent.egress-check`), and its Smoke task asserts the result.

## 2. mitmproxy over tcpdump, because bodies matter

tcpdump would see every packet but, for HTTPS, only encrypted bytes and the SNI host. We want method, path,
status and sizes of calls to `api.anthropic.com`, and later the bodies. mitmproxy terminates TLS and gives
us decrypted HTTP flows in a format we can script with a short addon (`capture_export.py`).

The price is trust: the agent must accept mitmproxy's CA. The CA is generated by the sidecar into the
`mitm-ca` volume (never the image or git), mounted read-only into the agent, and installed there at start.
The CA private key stays readable only by the sidecar's user.

## 3. The capture volume is read by the host, never mounted into the agent

`capture` is mounted only into `mitm` and into throwaway converter containers started from the host
(`ConvertTo-NetworkCapture`). The agent's compose service mounts `mitm-ca:ro` and nothing else from here.
That keeps the record out of the recorded party's reach, the same rule as decision 1, enforced by mounts.

## 4. The egress allowlist is exact host names, declared in `sidecar.yaml`

The agent has one legitimate destination, `api.anthropic.com`. The sidecar loads `src/addons/allowlist.py`,
which allows a flow only when its host is exactly one of `ALLOWED_HOSTS` (case-insensitive, no wildcards, no
suffix matching) and refuses everything else with a 403 whose body is `{"refused": true, "host": "<host>"}`.
A wildcard would buy flexibility the agent does not need and admit every host an attacker can register under it.

HTTPS is refused at `CONNECT`: no upstream connection is opened and no TLS handshake happens, so nothing reaches
a denied host. A request inside an allowed tunnel whose Host header names another host is refused too.
Refused flows are not dropped: they carry `refused` in their metadata, are written to `flows.mitm` like any
other, and come out of `ConvertTo-NetworkCapture` with `refused: true` and in the summary's `refusedHosts`.
What the agent tried to reach is as much part of the record as what it reached.

`ALLOWED_HOSTS` is set explicitly in `compose/sidecar.yaml` (the addon's default is the same value). Widening
it is a declared change to that line, reviewed like any other compose change, never an edit to the addon.
